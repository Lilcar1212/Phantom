# Hollow Oath: Blender → Roblox pipeline

Everything is generated by Python scripts running Blender 5.0 headless (`pip install bpy`), so every asset can be rebuilt from source:

```
python3 tools/gen_textures.py            # shared PBR texture library  -> textures/
python3 scripts/p1_00_test_cube.py       # scale / orientation test cube
python3 scripts/p1_01_layout_plan.py     # city layout plan (png + json)
python3 scripts/p1_10_roof_irimoya.py    # irimoya roofs S/M/L (HO_RENDER=0 skips renders)
```

## 1. Scale test: check this first

`assets/Phase0/Test/HO_Test_ScaleCube_1x1x1.fbx` is a 1×1×1 cube with its pivot at bottom-centre. Each face carries a label (FRONT / BACK / LEFT / RIGHT / TOP / BOTTOM) from `textures/Debug_Faces/`.

**Exact Blender FBX export settings used for every asset** (`tools/ho.py → FBX_SETTINGS`):

| Setting (Blender UI) | Value |
|---|---|
| Scene Unit System / Unit Scale | Metric / **1.0** (1 Blender unit = 1 stud) |
| Limit to | Selected Objects |
| Object Types | Mesh, Armature, Empty |
| **Scale** | **1.00** |
| **Apply Scalings** | **FBX Units Scale** |
| Apply Unit | ✔ |
| **Forward** | **-Z Forward** |
| **Up** | **Y Up** |
| **Apply Transform** (bake space transform) | ✔ (the axis conversion is baked into the vertices, so objects carry no 90° rotations) |
| Apply Modifiers | ✔ |
| Smoothing | Face |
| Tangent Space | ✔ |
| Add Leaf Bones | ✘ |
| Path Mode / Embed Textures | Strip / ✘ (textures are uploaded to SurfaceAppearance separately) |

I checked the exported file with `tools/fbx_inspect.py`, a small binary FBX reader. The raw vertex coordinates are exactly **−0.5…0.5 (X), 0…1 (Y), −0.5…0.5 (Z)**, with UpAxis = Y. The file declares `UnitScaleFactor = 100`, i.e. 1 file unit = 1 metre.

**Roblox import (3D Importer):**
1. Import the `.fbx`.
2. In the import settings, under **File Dimensions → Scale Unit**, choose **Stud**. The importer converts using the unit the file declares; left on *Meter*, it would scale by 3.57 (1 m = 3.57 studs).
3. Leave "Set Pivot to Origin" off. Our pivots are already baked at bottom-centre.
4. Check the result: the MeshPart `Size` should read **1, 1, 1**, and the red **FRONT** face should point along the part's LookVector (−Z). Up is +Y. The green **RIGHT** face is +X.

If the cube comes in at any other size, tell me the Size Roblox shows and I'll change `global_scale` once in `tools/ho.py`. Every asset gets re-exported from that one setting.

## 2. Conventions

* **1 unit = 1 stud.** Door ≈ 7 studs, character ≈ 5 studs, floor height 9 studs, grid 4 studs.
* **Front = Blender +Y**, which exports as Roblox −Z. Blender +Z = Roblox +Y (up). Blender +X = Roblox +X (the asset's right side).
* **Pivot:** bottom-centre of the bounding box. Transforms are applied and scale is 1.
* **Footprints** snap to the 4-stud grid (walls 8/12/16 wide). Roofs cover exactly the building footprint: the outer faces of the walls.
* **Roofs:** the roof's lowest point (z = 0) is the wall top. Place the roof at *wall height* and it seats correctly. The eaves overhang beyond the footprint.
* **Naming:** `HO_<Category>_<Name>_<Variant>`. Multi-mesh assets get suffixes such as `_Tiles` and `_Frame`, all sharing one pivot.
* **One texture set per mesh object.** A Roblox MeshPart holds only one SurfaceAppearance, so every exported mesh object uses exactly one material. Any object that used several materials is split on export into `<Object>__<TextureSet>` (e.g. `HO_Bldg_Machiya_C_Structure__Plaster_White`, `…__Timber_Dark`). Single-material objects keep their name. `MANIFEST.md → Mesh objects and their texture set` lists the set for every mesh object.
* **Triangles:** max 20,000 per mesh object. Every asset is triangulated on export.
* **Normals:** exported as face-smoothing groups. Curved tiles are smooth; boxes and edges are hard.

## 3. Textures (shared PBR library)

`textures/<Set>/HO_T_<Set>_{Color,Normal,Roughness,Metalness}.png`, all 1024×1024 and seamlessly tileable. Normal maps are tangent-space, OpenGL (+Y). Upload each set once to a `SurfaceAppearance` (ColorMap / NormalMap / RoughnessMap / MetalnessMap) and reuse it on every MeshPart that uses that material.

| Set | Use | Authored density |
|---|---|---|
| RoofTile_Clay | smoked ibushi-gawara tiles | 4 studs / tile |
| Timber_Dark, Timber_Light | stained / hinoki timber (grain along U) | 4 studs |
| Plaster_White | walls; V spans one 9-stud floor, with a dirt band at the base | 4 × 9 studs |
| Stone_Granite | individual ishigaki stones, rocks | 4 studs |
| Stone_Fitted | fitted-block faces (plinths, quay caps) | 4 studs |
| Cobblestone | streets, squares | 4 studs |
| Wood_Planks | decks, floors, piers | 4 studs (0.5-stud boards) |
| Gold_Leaf | shachihoko, ornaments, caps | 4 studs |
| Iron_Wrought | straps, fittings, weapons racks | 4 studs |
| Shoji_Paper | shoji panels, lanterns | 4 studs |

UVs are world-scaled (0.25 UV per stud), so tiling textures line up between modules and texel density is the same everywhere.

## 4. Checks run on every asset (`tools/ho.py → check`)

* triangle count per mesh / per material, compared against 20k
* pivot at bottom-centre
* footprint on the 4-stud grid
* **floating parts:** every connected piece must touch (bounding-box contact, 0.03-stud tolerance) a chain of pieces that reaches the ground plane
* **inverted parts:** closed pieces with negative signed volume (normals facing in)
* texture sizes ≤ 1024
* preview renders: 3/4 and front views, plus side and underside for roofs, all under golden-hour light
